In this tutorial you build a small business website with Astro and AtMyApp. By the end you will have:

- a **homepage** whose headline, introduction and image your client edits,
- a **services** list with one generated page per service,
- **page titles, descriptions and social images** managed from the dashboard,
- a **contact form** that needs no backend,
- a **deployment** that rebuilds when your client publishes.

It takes about 30 minutes. You need **Node.js 22.14 or newer**, an AtMyApp account and, for the last part, a GitHub account.

<Aside type="tip" title="Want the finished starter instead?">
`npm create atmyapp@latest` scaffolds an Astro + Tailwind site that is already wired to AtMyApp. This tutorial builds the same pieces one at a time, so you understand each of them.
</Aside>

## 1. Create a project and copy its keys

<Steps>

1. Sign in at [app.atmyapp.com](https://app.atmyapp.com) and create a project for this website.

2. Open **Settings → API keys** and create a key. Copy two values:
   - the **Project API URL**: `https://edge.atmyapp.com/v0/projects/<project-id>`
   - the **API key**

   Both are public. They let a website read published content and send forms.

3. Open **Settings → CLI keys**, create a key, and copy the `atmyapp use …` command shown there. A CLI key can change your schema, so keep it private.

</Steps>

See [Keys and URLs](/concepts/how-it-works/#keys-and-urls) if you're unsure which value goes where.

## 2. Create the Astro site

<Steps>

1. Create a minimal Astro project and install the AtMyApp packages:

   <Tabs syncKey="pm">
   <TabItem label="npm">
   ```sh
   npm create astro@latest my-site -- --template minimal --yes
   cd my-site
   npm install @atmyapp/astro @atmyapp/core @atmyapp/structure
   npm install --save-dev @atmyapp/cli
   ```
   </TabItem>
   <TabItem label="pnpm">
   ```sh
   pnpm create astro@latest my-site --template minimal --yes
   cd my-site
   pnpm add @atmyapp/astro @atmyapp/core @atmyapp/structure
   pnpm add --save-dev @atmyapp/cli
   ```
   </TabItem>
   <TabItem label="yarn">
   ```sh
   yarn create astro my-site --template minimal --yes
   cd my-site
   yarn add @atmyapp/astro @atmyapp/core @atmyapp/structure
   yarn add --dev @atmyapp/cli
   ```
   </TabItem>
   </Tabs>

2. Add the website keys to a `.env` file in the project root:

   ```dotenv title=".env"
   ATMYAPP_API_URL=https://edge.atmyapp.com/v0/projects/<project-id>
   ATMYAPP_API_KEY=<api-key>
   ```

3. Register the integration and set your production address in `astro.config.mjs`:

   ```js title="astro.config.mjs" ins={2,5-6}
   import { defineConfig } from "astro/config";
   import atmyapp from "@atmyapp/astro";

   export default defineConfig({
     site: "https://www.example.com",
     integrations: [atmyapp()],
   });
   ```

   `site` is used for canonical links and form redirects. Use the real domain, even before it's live.

4. Connect the CLI by pasting the command you copied from **Settings → CLI keys**:

   ```sh
   npx atmyapp use --url https://api.atmyapp.com/v0/projects/<project-id> --token <cli-key>
   ```

   The CLI checks the key, saves it to `.ama/session.json`, and adds that file to `.gitignore`.

</Steps>

## 3. Describe the editable content

Create `atmyapp.schema.ts` in the project root. It lists everything your client can edit:

```ts title="atmyapp.schema.ts"
import {
  defineCollection,
  defineDocument,
  defineSchema,
  defineSubmission,
  s,
} from "@atmyapp/structure";

export default defineSchema({
  definitions: {
    home: defineDocument({
      description: "The homepage.",
      fields: {
        headline: s.string({
          max: 80,
          description: "Large heading at the top of the homepage.",
        }),
        intro: s.longText({ description: "One or two sentences under the headline." }),
        hero: s.image({ optional: true, description: "Wide photo beside the headline." }),
      },
    }),
    services: defineCollection({
      description: "Services we offer. Each one gets its own page.",
      fields: {
        title: s.string({ max: 60 }),
        slug: s.slug({ source: "title" }),
        summary: s.string({ max: 160, description: "Shown on the homepage card." }),
        details: s.longText({ description: "Shown on the service's own page." }),
      },
    }),
  },
  submissions: {
    contact: defineSubmission({
      description: "Contact form on /contact.",
      fields: {
        name: s.string({ max: 100 }),
        email: s.email(),
        message: s.longText({ min: 10, max: 5000 }),
      },
    }),
  },
});
```

A few things to notice:

- `home` is a **document**: one set of fields. `services` is a **collection**: many entries with the same fields.
- `description` text is shown to your client and to the AI assistant. Say where the text appears.
- `max` lengths protect your layout. AtMyApp refuses content that breaks them.
- `s.slug()` generates a URL-safe identifier from the title, and keeps it stable afterwards.

Now upload the schema:

```sh
npx atmyapp migrate --dry-run   # compile and check it locally
npx atmyapp migrate             # upload it to the project
```

`migrate` shows a plan of what changes in the project and asks before it touches existing content. Your project is empty, so it applies straight away. The `contact` form now exists too.

## 4. Add the first content

Your website reads **published** content, so publish something before you render it.

<Steps>

1. In the dashboard, open **Content → Home**. Fill in the headline and introduction, and optionally upload an image.

2. Open **Content → Services** and add two or three entries.

3. Open **Settings → Website settings**. Enter the website name and a default description. These feed the page titles and social tags in the next step.

4. Click **Review & publish** and publish everything.

</Steps>

## 5. Add a layout with managed SEO tags

Create a layout that every page uses. `AtMyAppHead` renders the title, description, canonical link, social tags and icons from **Website settings**, with per-page overrides.

```astro title="src/layouts/BaseLayout.astro"
---
import AtMyAppHead from "@atmyapp/astro/components";

interface Props {
  title?: string;
  description?: string;
  image?: string;
}
const { title, description, image } = Astro.props;
---

<html lang="en">
  <head>
    <meta charset="utf-8" />
    <meta name="viewport" content="width=device-width, initial-scale=1" />
    <AtMyAppHead title={title} description={description} image={image} />
  </head>
  <body>
    <header><a href="/">Home</a> · <a href="/contact/">Contact</a></header>
    <main><slot /></main>
  </body>
</html>
```

Leave `<title>` and description tags out of your layout: `AtMyAppHead` owns them. If the website name is "Altana", `title="Services"` renders `Services · Altana`. More in [Metadata and SEO](/guides/astro-metadata/).

## 6. Render the homepage

Replace `src/pages/index.astro`:

```astro title="src/pages/index.astro"
---
import { getAtMyApp } from "@atmyapp/astro/server";
import schema from "../../atmyapp.schema";
import BaseLayout from "../layouts/BaseLayout.astro";

const ama = getAtMyApp(Astro, { schema });
const home = await ama.storage.getValue("home");
const services = await ama.collections.list("services");
---

<BaseLayout>
  <h1>{home.headline}</h1>
  <p>{home.intro}</p>
  {home.hero && <img src={home.hero.url} alt="" width="1200" />}

  <h2>Services</h2>
  <ul>
    {
      services.map((service) => (
        <li>
          <a href={`/services/${service.slug}/`}>{service.title}</a>
          <p>{service.summary}</p>
        </li>
      ))
    }
  </ul>
</BaseLayout>
```

Start the dev server with `npm run dev` and open the page. You should see your published headline and services.

- `getAtMyApp(Astro, { schema })` returns a client configured from your `.env`. Passing the schema makes every read typed: try `home.` in your editor.
- `getValue("home")` returns the document's fields. `collections.list("services")` returns an array of entries, newest first.
- Image fields arrive as an object with a `url`.

<Aside type="caution" title="Content not showing?">
Check that you published it, and that `ATMYAPP_API_URL` is the **edge** URL with the `/v0/projects/<id>` path. Errors stop the page by default, so you see the reason instead of an empty page. See [Troubleshooting](/troubleshooting/).
</Aside>

## 7. Generate a page per service

Create `src/pages/services/[slug].astro`:

```astro title="src/pages/services/[slug].astro"
---
import { getAtMyApp } from "@atmyapp/astro/server";
import { CollectionsFilter as F } from "@atmyapp/core";
import schema from "../../../atmyapp.schema";
import BaseLayout from "../../layouts/BaseLayout.astro";

// Runs during static builds: one page per published service.
export async function getStaticPaths() {
  const services = await getAtMyApp({ schema }).collections.list("services");
  return services.map((service) => ({ params: { slug: service.slug } }));
}

const ama = getAtMyApp(Astro, { schema });
const service = await ama.collections.first("services", {
  filter: F.eq("slug", Astro.params.slug!),
});
if (!service) return new Response("Not found", { status: 404 });
---

<BaseLayout title={service.title} description={service.summary}>
  <h1>{service.title}</h1>
  <p>{service.details}</p>
</BaseLayout>
```

Why both parts? Production builds are **static**, so Astro needs `getStaticPaths()` to know which pages to generate. During development and in previews the site renders **per request**, so the page looks the service up by its slug. The same file works in both modes. [Modes and previews](/guides/astro-previews/) explains this in detail.

<Aside>
`getStaticPaths()` has no `Astro` object, so it calls `getAtMyApp({ schema })` without one. That form works only in static builds. In `astro dev` you'll see the warning `getStaticPaths() ignored in dynamic page`; that's expected.
</Aside>

## 8. Add the contact form

Create `src/pages/contact.astro`:

```astro title="src/pages/contact.astro"
---
import AtMyAppForm from "@atmyapp/astro/form";
import BaseLayout from "../layouts/BaseLayout.astro";
---

<BaseLayout title="Contact">
  <h1>Get in touch</h1>
  <AtMyAppForm submission="contact" enhance>
    <label>Name <input name="name" required /></label>
    <small data-atmyapp-error="name"></small>

    <label>Email <input name="email" type="email" required /></label>
    <small data-atmyapp-error="email"></small>

    <label>Message <textarea name="message" required minlength="10"></textarea></label>
    <small data-atmyapp-error="message"></small>

    <button type="submit">Send</button>
  </AtMyAppForm>
</BaseLayout>
```

The form posts straight to AtMyApp, so it works on a static site. The input `name`s match the fields in your schema. With `enhance`, the form sends without reloading, shows errors next to the fields, and shows a thank-you message. Without JavaScript it still works as a normal HTML form. A hidden spam trap is added for you.

To send visitors to your own thank-you page instead, add `returnTo="/thank-you/"`. It resolves against `site`, so it points at your production domain.

Send yourself a message. To watch it arrive, run this in a second terminal:

```sh
npx atmyapp submissions tail contact
```

Messages sent from `localhost` are stored as **local development**, so they never reach your client's inbox or notifications. More in [Astro forms](/guides/astro-forms/).

## 9. Build it

```sh
npm run build
```

The build fetches all content and writes plain HTML to `dist/`. A failed read fails the build, so a broken connection never ships an empty page. Your project now looks like this:

<FileTree>
- .ama/
  - session.json (private, ignored by git)
- src/
  - layouts/
    - BaseLayout.astro
  - pages/
    - index.astro
    - contact.astro
    - services/
      - [slug].astro
- .env
- astro.config.mjs
- atmyapp.schema.ts
- package.json
</FileTree>

Commit everything except `.env` and `.ama/session.json`, and push it to a GitHub repository.

## 10. Deploy with AtMyApp hosting

<Steps>

1. In the dashboard, open **Settings → Hosting** and connect your GitHub repository.

2. Use `npm run build` as the build command and `dist` as the output directory.

3. Start the first build. AtMyApp provides `ATMYAPP_API_URL` and `ATMYAPP_API_KEY` to the build, so you don't add them yourself.

4. When the build is live, add your domain in the same place.

</Steps>

New websites rebuild automatically when your client publishes, so you're done. Prefer another host? See [Deploy](/deployment/#another-static-host).

## 11. Try the client's side

Edit the homepage headline in the dashboard, but don't publish yet. Click **Preview**: AtMyApp opens your site on a preview server with the draft applied. Publish, and a new build goes live a minute or two later.

That loop (edit, preview, publish) is what your client will do every day. Before you hand the project over, read [Hand over to your client](/ai-assistant/).
