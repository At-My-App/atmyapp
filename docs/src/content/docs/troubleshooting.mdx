Start by making errors visible. With `@atmyapp/core`, set `errorPolicy: "throw"` while you investigate; the default quietly returns empty values and only logs a warning to the console. `@atmyapp/astro` throws by default.

## Connection and keys

| You see | Cause | Fix |
| --- | --- | --- |
| `Invalid API key` | The key is wrong, revoked, or a CLI key was used | Copy an API key from **Settings → API keys**. CLI keys don't work for content. |
| `API key does not belong to this project` | The URL and the key are from different projects | Copy both from the same project. |
| `404` on every read, or HTML instead of JSON | The base URL is wrong | Use `https://edge.atmyapp.com/v0/projects/<id>`, including `/v0/projects/<id>`. Not `api.atmyapp.com`. |
| `AtMyApp: set ATMYAPP_API_KEY.` | Astro can't find the key | Add it to `.env`, or to your host's build environment. Restart `astro dev` after editing `.env`. |
| `AtMyApp: set ATMYAPP_BASE_URL or ATMYAPP_API_URL to your project API URL.` | Astro can't find the URL | Add `ATMYAPP_API_URL` the same way. |
| `AtMyApp: invalid project API URL.` | The URL has a query string, a fragment or credentials | Use the plain URL from the dashboard. |

## Content

| You see | Cause | Fix |
| --- | --- | --- |
| `File not found` / empty document | The document was never published, or its path differs from the schema | Publish it in the dashboard. Check the definition name and `path`. |
| Empty values and a console warning `returning quiet empty state` | A read failed under the default `quiet-empty` policy | Set `errorPolicy: "throw"` to see the real error. |
| `getValue is not a function` | The client was created without `schema` | Pass `schema` to `createAtMyAppClient` or `getAtMyApp`. |
| A collection returns 50 entries when there are more | 50 is the per-request maximum | [Paginate](/guides/collections/#paginate). |
| `AND inside OR is not supported` / `NOT is not supported` | The filter can't be expressed in a query | Filter the results in your code. See [Filter](/guides/collections/#filter). |
| A filter on a nested field matches nothing | Only top-level fields can be filtered | Filter in your code, or move the field to the top level. |
| A reference field shows an ID, not the entry | References store IDs | [Resolve references](/guides/collections/#resolve-references). |
| Locale-specific reads fail for images | Files aren't translated | Read images without `locale`. |

## Publishing and freshness

| You see | Cause | Fix |
| --- | --- | --- |
| A published edit doesn't appear on a static site | The site wasn't rebuilt | On AtMyApp hosting, check the build in **Settings → Hosting**. Elsewhere, rebuild. See [Deploy](/deployment/). |
| An edit takes up to a minute on a server-rendered site | Published reads are cached for up to 60 seconds | Expected. Use `mode: "priority"` only where you must see it at once. |
| A build fails after your client published | The new content broke a read, or a required value is missing | Read the build log. The previous version stays live meanwhile. |

## Previews

| You see | Cause | Fix |
| --- | --- | --- |
| The preview shows published content | The page was rendered statically | Previews need dynamic rendering. Use an AtMyApp preview server, or `astro dev`. See [Astro modes](/guides/astro-previews/). |
| `AtMyApp: preview access could not be verified. Reopen the preview from AtMyApp.` | The preview key expired or the session ended | Click **Preview** again in the dashboard. |
| `A signed, scoped content-staging capability is required for preview access.` | `amaPreviewKey` was edited or copied incorrectly | Reopen the preview from the dashboard. |
| Drafts disappear after clicking a link | The link dropped `amaPreviewKey` | AtMyApp preview servers keep it. On your own host, carry it through internal links. |
| `AtMyApp: pass Astro's context in dynamic mode` | `getAtMyApp()` was called without `Astro` outside `getStaticPaths()` | Call `getAtMyApp(Astro)` in page code. |

## Schema and CLI

| You see | Cause | Fix |
| --- | --- | --- |
| `AtMyApp session not configured. Run 'atmyapp use' first…` | The CLI isn't connected in this folder | Run `npx atmyapp use` in the project root. |
| `CLI key belongs to project '…'` | The CLI URL and key are from different projects | Copy the command from **Settings → CLI keys** again. |
| No schema file found | The file name isn't recognised | Name it `atmyapp.schema.ts` (or `.mts`, `.js`, `.mjs`, `.json`) in the project root. |
| `The migration is blocked. Nothing was changed.` | The change would make stored content invalid | Read the plan. See [What the plan blocks](/guides/schema-changes/#what-the-plan-blocks-and-how-to-unblock-it). |
| `This plan changes stored content. Review it and run again with --yes` | A confirmation was needed without a terminal | Review the plan, then rerun with `--yes`. |
| `Content or schema changed after this plan was made` | Someone edited content during the migration | Run `migrate` again to review a fresh plan. |
| `The server did not confirm the migration` | The connection dropped | Run `npx atmyapp migrate-status <operation-id>`. |

## Forms

| You see | Cause | Fix |
| --- | --- | --- |
| `AtMyApp: submission type "…" was not found.` | The form doesn't exist in the project | Define it under `submissions` and run `migrate`, or create it in the dashboard. Check the spelling. |
| "This form is currently closed." | The form isn't accepting responses | Open it in the form's settings. Static sites show the state from build time. |
| `origin_not_allowed` | The website isn't in the form's **Allowed websites** | Add the exact origin, such as `https://www.example.com`. |
| `captcha_*` codes | Widget, keys or domains | See [Spam protection → Troubleshooting](/guides/form-spam-protection/#troubleshooting). |
| A field arrives empty or under *Ignored fields* | The input `name` doesn't match the schema | Match the field names exactly. |

For a step-by-step report of what happened to a submission, send it in [test mode](/guides/forms/#try-it-without-filling-the-inbox), or watch `npx atmyapp submissions tail`. All error codes are listed in [Form limits and errors](/reference/submissions/#error-codes).

## Search in these docs

Search is built during `astro build`. In `astro dev` it shows a notice instead of results; run `astro build && astro preview` to try it.

## Still stuck?

Email [contact@atmyapp.com](mailto:contact@atmyapp.com) with the page or command, what you expected, and the exact error. A [diagnostics report](/guides/diagnostics/) helps a lot. Never send CLI keys or preview URLs.

<Aside>
API keys are public, so sharing one in a support email is fine. CLI keys are not.
</Aside>
